# P1.5 — Failure-adaptation demo (nice-to-have)

**Goal.** A single ~1000 s sim showing the framework's response to a runtime
actuator failure: the control law is unchanged, only the allocation layer sees
the reduced actuator set, so pointing degrades gracefully and recovers.

## Status
Already implemented as `generate_fig_failure.py` (Paper 1 §V-D), using the
`config['fail']` hook in `_paper1_sim.simulate` (no framework modification).
Regenerated at paper scale for this round.

## Environment
- Python 3.12.13, NumPy 2.2.6, SciPy 1.15.3; Patricks-MacBook-Pro.local
  (Darwin 25.4.0, arm64). Branch `paper2-datagen`, commit `790880a` + this
  changeset. SALTRO `fd7d24c`.

## Method
- Config **3MTQ+3RW**, fixed ECI target, seed 7, tf = 1000 s, dt = 2 s,
  controller `MTQ_w_RW_LP` (canonical gains 5e-5/1e-3/1e-3).
- At t = 500 s, reaction wheel #3 (`act_index = 3`) fails: its torque bound is
  set to 0. The LP allocation then sees only the remaining 2 RW + 3 MTQ.

## Results

| Config | ss err pre (deg) | max err post (deg) | ss err post (deg) | recovery (s) |
|---|---:|---:|---:|---:|
| 3MTQ+3RW (lose 1 RW) | 0.007 | **0.005** | 0.003 | **0.0** |

Outputs: `output_data/fig_failure.png` (pointing error with failure instant
marked), `output_data/fig_failure_u.png` (actuator commands showing
reallocation), `output_data/tab_failure.{tex,csv,md}`.

## Reading guide / honest framing
- **Graceful degradation is essentially invisible here**, by design: a 3+3
  spacecraft that loses one wheel still has 2 RW + 3 MTQ — full 3-axis
  authority with redundancy — so the LP allocation reallocates the lost wheel's
  share to the remaining actuators with **no measurable pointing degradation**
  (post-failure max error 0.005°, instant recovery). The control law never
  changes; only the allocation layer adapts. This is exactly the framework's
  separation-of-concerns claim.
- **Caveat:** because 3+3 is over-actuated, this is a *redundancy* demonstration
  rather than a stress test. A more dramatic transient would require failing
  more actuators (e.g. two wheels, or a wheel on 3+1 leaving the system
  controllability-marginal). The clean result is the right one for the
  "allocation adapts transparently" message; the dramatic version is a
  one-line `FAILED_ACT_INDEX` / config change if a visible transient is wanted.
