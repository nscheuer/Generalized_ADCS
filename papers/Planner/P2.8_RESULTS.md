# P2.8 — Planner robustness to plan-vs-sim model mismatch

**Goal.** Quantify how the plan-and-track planner tolerates a mismatch between
the model it plans on and the plant it flies: inertia (J) error and
geomagnetic-field (B) error. Single-trajectory demos (not MC). Paper 2,
robustness of feasibility-aware planning.

## Environment
- Python 3.12.13, NumPy 2.2.6, SciPy 1.15.3; Patricks-MacBook-Pro.local
  (Darwin 25.4.0, arm64). Branch `paper2-datagen`, this changeset. SALTRO `fd7d24c`.

## Method (paper-citable)
- Config **3+1**, ECI-pointing acquisition to a fixed target
  `[0.30, 0.60, 0.74]`, tf = 1000 s, dt = 1 s, `Plan_and_Track_LQR`.
- **Inertia mismatch:** the controller plans *and* tracks on an estimated sat
  whose inertia is scaled, `est J = s · true J` (via `Satellite.update_J`,
  which propagates to the C++ planner through `change_Jcom` and to the TVLQR
  gains); the plant integrates the *true* J. Levels `s ∈ {0.7, 0.85, 1.0,
  1.15, 1.3}`.
- **B-field magnitude mismatch:** the planner plans on the nominal IGRF field;
  the realized field used by the plant dynamics *and* onboard sensing is scaled,
  `B_plant = s · B_planned` (the magnetorquer torque `τ = m × B` is therefore
  off from the plan's assumption). Levels `s ∈ {0.7, 0.85, 1.0, 1.15, 1.3}`.
- **B-field rotation mismatch:** the realized field is *rotated* by `θ` about a
  fixed axis (`kind="Brot"`), `B_plant = R(θ) · B_planned`. This is more
  adversarial than magnitude scaling because the magnetorquer torque plane
  (⟂ B) rotates, so the achievable torque *directions* differ from the plan's.
  Angles `θ ∈ {0, 15, 30, 45, 60}°`.
- One trajectory per level; pointing error = boresight-vs-target angle (Paper-2
  metric). Convergence/settling threshold 5°.

## Reading guide / honest framing
- **The planner is robust to ±30% inertia, ±30% B-field magnitude, and up to
  ~45° B-field rotation mismatch.** Final pointing accuracy is essentially
  unaffected (~0.01–0.03° across those levels) — the TVLQR feedback senses the
  true state and drives to the fixed target regardless of the reference
  trajectory's model error, and the LP allocation re-projects onto whatever
  field is actually present. The plan is a *reference*, not an open-loop
  command; closed-loop tracking absorbs the mismatch. Positive result for the
  feasibility-aware-planning claim.
- **The one measurable effect is settling time under inertia *over*estimate.**
  Settling rises monotonically with `est J / true J`: 181 s (s=0.7) → 207 s
  (nominal) → 230 s (s=1.3). Planning on a heavier-than-real inertia yields a
  more sluggish reference/gain set, so acquisition is slower — but it still
  converges to the same accuracy. Underestimating J is, if anything, slightly
  faster. B-magnitude mismatch barely moves settling (203–210 s).
- **B-field rotation is the more adversarial B error — and it has a threshold.**
  Magnitude scaling barely moves anything (it just re-scales achievable torque,
  which feedback absorbs), but *rotating* the field turns the magnetorquer
  torque plane away from the plan's. Up to 45° this is still absorbed
  (~0.01°, settle ~205 s); at **60°** it bites: settling nearly doubles to
  **372 s** with a ~3.6° transient excursion before it recovers. So there is a
  robustness margin (~45°) beyond which large field-direction error materially
  slows recovery — useful to quote as the planner's tolerance band.
- **Caveat — steady-state vs transient.** Because the task is regulation to a
  *static* target, the steady state is feedback-determined and therefore
  insensitive to plan error; the mismatch shows up in the transient (settling /
  excursion). A maneuver requiring the plan to be *executed* precisely (a tight
  time-constrained slew, or the spinning terminal state of P2.2) would expose
  plan error more — the natural next test.
- Single-trajectory demos, as scoped; an MC over the mismatch distribution is
  the heavier follow-up.
