# P2.4 — TVLQR vs single-step MPC (trajectory tracking)

**Goal.** Quantify the trajectory-tracking difference between the TVLQR
feedback law and a single-step (receding-horizon, one step) MPC tracker, both
running on the *same* SALTRO-planned trajectories. Paper 2, tracking
architecture comparison.

## Environment
- Python 3.12.13, NumPy 2.2.6, SciPy 1.15.3
- Host: Patricks-MacBook-Pro.local (Darwin 25.4.0, arm64)
- Branch `paper2-datagen`, commits `8692b69` (controller + generator),
  `017a939`/this changeset (metric fix). SALTRO submodule `fd7d24c`.

## Method (paper-citable)
- Config **3+1** (3 MTQ + 1 RW, beavercube2), reduced / vector-pointing task.
- **Paired** design: two MC campaigns, identical `base_seed=42` and `MCConfig`
  (random IC quaternion, body rate 0.1–1.0°/s, random ECI goal, random circular
  orbit), so trial *i* sees the same scenario under both trackers. Because both
  trackers subclass the same planner and share `calculate_trajectory`, they
  also track the **same planned trajectory** per trial — the only difference is
  the per-step law.
- 100 trials, tf = 1000 s, dt = 1 s. Convergence = final pointing error < 5°
  using the locked Paper-2 metric (body boresight [0,1,0] rotated into ECI vs
  target; `analyze_p2_matrix` convention).
- **TVLQR**: `u = u_ref − K dx`, post-hoc saturation clip.
- **MPC** (`Plan_and_Track_SingleStepMPC`): bounded 1-step QP (BVLS) minimising
  the **K-gain-weighted** next-step error from a forward RK4 prediction at the
  actual state/B-field, with a smooth blend to a goal-directed mode above 30°
  tracking error. The value-function weight uses the surrogate **S ≈ KᵀK**
  (the C++ SALTRO solver does not expose the cost-to-go S; the TVLQR gains K
  are available and KᵀK is a usable proxy).

## Results (100 paired trials, 3+1)

| Metric | TVLQR | MPC | Δ (TVLQR−MPC) |
|---|---:|---:|---:|
| Convergence (<5°) | **100 %** | **62 %** | +38 pts |
| Final error, mean | 0.12° | 12.96° | −12.85° |
| Final error, p95 | 0.41° | 57.4° | — |
| RMS error, mean | 30.9° | 39.4° | −8.6° |
| Settling time, mean | 293 s | 668 s | −364 s |
| Control effort, mean | 19.0 | 47.8 | −28.8 |
| Solve time / step, median | **0.016 ms** | **5.28 ms** | ~330× |

(RMS includes the large-angle acquisition transient, hence tens of degrees for
both; the discriminating quantity is the **final** error / convergence.)

## Headline & honest caveats
- **On this testbed TVLQR clearly beats the single-step MPC**: 100% vs 62%
  convergence, 0.12° vs 13° final error, while spending **2.5× less control
  effort** and **~330× less compute per step** (0.016 ms vs 5.3 ms). Both are
  far under a 1 Hz budget, so compute is not the deciding factor — tracking
  quality is, and TVLQR wins.
- **Why MPC underperforms here — mechanism understood.** The committed
  single-step MPC was validated on a branch where the planner exposes the true
  cost-to-go S; on `paper2-datagen` the C++ solver returns only K, so this run
  uses the **S ≈ KᵀK surrogate**. KᵀK is not the value-function Hessian, so the
  MPC's state-error weighting is approximate; combined with the goal-directed
  blend above 30° (which fires often given the random large-angle ICs) and the
  default regularisation (`control_reg = 1e-3`), the bounded QP trades tracking
  fidelity for bounded-but-misweighted corrections. This is a faithful "as-
  ported, untuned" comparison, **not** an MPC-optimal one.
- **Reading for the paper.** The defensible claim is architectural: a single-
  step bounded-QP tracker is *feasible and cheap enough for 1 Hz onboard use*
  (5.3 ms/step), but on a well-conditioned planned trajectory the Riccati TVLQR
  law it is meant to approximate is both more accurate and far cheaper. The MPC
  earns its keep only where TVLQR's post-hoc clipping fails (hard saturation) —
  not demonstrated as a net win on this nominal 3+1 reduced campaign. If a
  positive MPC result is wanted, the next levers are (a) exposing the true S
  from the C++ solver and (b) tuning `control_reg` / the 30° blend threshold;
  both are noted, neither was done here.

## Tuning pass (does disabling the goal-blend / tuning control_reg close the gap?)
Quick 25-trial paired sweep (`generate_p2.4_tuning.py`, `disable_goal_blend`
knob added to the MPC):

| Variant | Conv % | mean final (deg) | effort |
|---|---:|---:|---:|
| TVLQR | **100** | 0.22 | 20.6 |
| MPC default (blend on, reg=1e-3) | **64** | 8.3 | 33.0 |
| MPC blend-off (pure tracking) | 56 | 14.3 | 35.1 |
| MPC blend-off, reg=1e-2 | 36 | 38.1 | 34.9 |

**Conclusion:** the committed MPC config (goal-blend ON, `control_reg=1e-3`) is
already the *best* MPC variant — disabling the blend (56%) or raising
`control_reg` (36%) both make it worse. So the gap to TVLQR is **not** a
blend/reg tuning issue; it is the `S≈KᵀK` value-function surrogate. Closing it
requires exposing the true cost-to-go `S` from the C++ solver (heavy: submodule
change + rebuild), not a tuning tweak. TVLQR remains the right tracker for this
nominal 3+1 reduced campaign; MPC's niche is hard-saturation regimes (not
exercised here). Tuning data: `output_data/P2.4_tuning_<ts>.json`.
