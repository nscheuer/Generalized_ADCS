# P2.6 — Online replan after disturbance

**Goal.** Demonstrate feasibility-aware *online* replanning: plan an open-loop
trajectory, track it closed-loop, inject an unexpected disturbance mid-
maneuver, re-solve from the perturbed state, and resume tracking on the new
trajectory. A single clean illustrative trajectory (not an MC).

## Environment
- Python 3.12.13, NumPy 2.2.6, SciPy 1.15.3; Patricks-MacBook-Pro.local
  (Darwin 25.4.0, arm64). Branch `paper2-datagen`, commit `ba53987` + this
  task's new script. SALTRO `fd7d24c`.

## Scenario (fully specified, paper-citable)
- Config **3+1** (3 MTQ + 1 RW, beavercube2). Goal: **anti-ram**
  (`AntiVelocity_Goal`) pointing acquisition. Start at rest, identity attitude
  (≈ 90° initial boresight error from the anti-ram target — see series).
- First plan: SALTRO/ALTRO acquisition over **tf = 1000 s**, dt = 1 s, TVLQR
  tracking. (A long horizon is used so the realized closed-loop tracks the
  plan; a 200 s horizon plans a 90° slew too aggressive for 3+1 magnetic
  authority to follow — documented below.)
- **Disturbance:** at t = 500 s (after acquisition has settled), an impulsive
  **+30° body rotation** about axis [0.864, −0.432, 0.259].
- **Replan trigger:** state-based — pointing error > 10° after the
  disturbance. It trips immediately (the kick → 26.7°).
- Re-solve a fresh trajectory from the perturbed state over the remaining
  horizon; resume tracking. A **no-replan counterfactual** (keep tracking the
  stale plan) is run on the identical disturbance for comparison.

## Results

| Quantity | Value |
|---|---:|
| Error at replan trigger | 26.7° |
| Replan solve time | **2.56 s** |
| Recovery time (error < 5° after replan) | 214 s |
| Final pointing error — replan | **0.01°** |
| Final pointing error — no replan | 0.36° |
| Control effort — replan | **17.5** |
| Control effort — no replan | 128.8 |

Outputs: `output_data/P2.6_replan_20260601_000000.json` (full series + scenario),
`output_data/fig_replan.{png,pdf}` (3 traces: original open-loop plan; disturbed
+ no replan; disturbed + replan; disturbance and replan events annotated).

## Reading guide / honest framing
- **Online replanning is feasible and efficient.** Re-solving from the
  perturbed state takes **2.56 s** and recovers to **0.01°** while spending
  **~7× less control effort** than tracking the stale plan (17.5 vs 128.8).
  The stale plan's TVLQR feedback *also* eventually recovers (0.36°) — the 30°
  kick is within the terminal hold's region of attraction — but it fights the
  disturbance with high-gain feedback (the large effort), whereas the replan
  lays down an efficient fresh path.
- **Recovery is not instantaneous (214 s)** — that is the physical re-slew time
  for a 30° correction on 3+1 magnetic+1-wheel authority, *not* the solver time
  (2.56 s). Reported honestly: the *planner* responds in seconds; the *plant*
  takes minutes to execute the correction.
- **Horizon caveat (documented, not hidden).** An earlier 200 s acquisition
  horizon (as the brief suggested) plans a 90° slew the 3+1 magnetic actuators
  cannot physically track — the realized error lagged the plan by ~20° even
  with no disturbance, muddying the demo and making a short-horizon replan
  *worse* than continuing the original plan. The 1000 s horizon keeps the plan
  within actuator authority so closed-loop tracking is faithful and the replan
  benefit (efficiency) is clean. This is itself a useful finding: replanning
  helps when the replanned trajectory is feasible for the hardware.
- Single illustrative trajectory, as scoped. A small sweep (disturbance
  magnitude, trigger threshold) is a natural extension but not required.
