# P2.3 — Sequential multi-goal Monte Carlo

**Goal.** Demonstrate the planner chaining several terminal pointing goals in
one plan — point at A, hold, slew to B, hold, slew to C — without intermediate
replanning or mode switching. Complements P2.2 (nonstatic terminal state):
together they support the "arbitrary terminal targets" claim.

## Environment
- Python 3.12.13, NumPy 2.2.6, SciPy 1.15.3; Patricks-MacBook-Pro.local
  (Darwin 25.4.0, arm64). Branch `paper2-datagen`, commit `d315220` + this
  task's new script. SALTRO `fd7d24c`.

## Method (paper-citable)
- Goal timeline (seconds): `0 → ECI_Goal A`, `300 → No_Goal`, `400 → ECI_Goal
  B`, `700 → No_Goal`, `800 → ECI_Goal C` (the existing `*_mixed` scenario).
  A, B, C are random unit ECI directions per trial, **paired across configs**.
- Configs **3+1** and **3+3**. 100 trials, paired seeds, tf = 1000 s, dt = 1 s,
  `Plan_and_Track_LQR` (ALTRO + TVLQR). One plan per trial through all goals
  (no per-goal replanning).
- Metrics per active window (A:[0,300), B:[400,700), C:[800,1000]): boresight
  pointing error vs the active goal (Paper-2 metric, boresight [0,1,0]).
  **Acquired** = min error in window < 5° (did the planner *hit* the goal);
  **held** = error still < 5° at window end.

## Reading guide / honest framing
- **The planner chains the goals in a single plan.** It reliably *acquires*
  the later goals (B 97–100%, C 100%) and the terminal goal C is also *held*
  (99–100%). This is the "arbitrary terminal targets, chained" demonstration.
- **Intermediate goals are acquired but not held** (held % is low for A, B).
  This is a property of single-shot multi-goal planning, **not** a failure: the
  optimizer plans one smooth trajectory through all goals, so it begins slewing
  toward the next goal before the current hold window ends (the error dips to
  ~0 at each goal, then rises as the next slew starts — visible in the
  representative figure). Only the final goal has no successor to anticipate,
  hence it is held.
- **Goal A acquisition is authority-limited on 3+1 (45%)** vs 3+3 (94%): the
  first goal requires the largest slew (from a random initial attitude within a
  300 s window), and 3 MTQ + 1 RW cannot always complete it in time, whereas
  full 3-wheel authority (3+3) can. This is the expected controllability
  gradient and is consistent with P1.2.
- **RW momentum** profiles (in the figure / JSON) show the wheels charging and
  discharging across the goal sequence without saturation runaway on 3+3.
- Headline the **acquisition** rates (did the planner hit each goal), not the
  window-end "held" rates, which penalise the planner for the very anticipation
  that makes single-shot multi-goal planning efficient.
