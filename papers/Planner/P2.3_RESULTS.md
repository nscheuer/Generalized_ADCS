# P2.3 — Sequential multi-goal Monte Carlo (widened windows)

**Goal.** The planner chains several terminal pointing goals in one plan —
point at A, hold, slew to B, hold, slew to C — without intermediate replanning
or mode switching. Complements P2.2 (nonstatic terminal state). v6 redo:
**widened, symmetric windows** so the first large slew (goal A) can complete.

## Environment
- Python 3.12.13, NumPy 2.2.6, SciPy 1.15.3; Patricks-MacBook-Pro.local
  (Darwin 25.4.0, arm64). Branch `paper2-datagen`, commit `2169290` + this
  changeset. SALTRO `fd7d24c`.

## Method (paper-citable)
- Symmetric timeline: `A active | no-goal | B active | no-goal | C active`,
  **equal active widths (500 s) and equal no-goal coasts (200 s)** → tf = 1900 s,
  dt = 1 s. A, B, C are random unit ECI directions per trial, **paired across
  configs** (base_seed = 42). `Plan_and_Track_LQR`, single plan through all
  three goals (no replan).
- Configs **3+1** and **3+3**, 100 trials each.
- Per active window: boresight error vs the active goal (Paper-2 metric,
  boresight [0,1,0]). **Acquired** = min error in window < 5° (did the planner
  *hit* the goal); **held** = error still < 5° at window end.

## Window-iteration history (per the brief)
The active window was sized on 3+1 goal-A acquisition (the diagnostic — the one
large slew from a random initial attitude):

| Active / coast | tf | 3+1 goal-A acquired |
|---|---:|---:|
| 300 / 100 (original) | 1000 s | 45% (too low) |
| 400 / 200 | 1700 s | 83% (in the brief's 70–85% band) |
| **500 / 200 (selected)** | **1900 s** | **96% (reliably acquires)** |

500 s was selected (operator preference for "reliably acquires all goals" over
"operating near the limit"); 400 s remains the option if the brief's 70–85%
band is preferred. Coast held at 200 s throughout (B held-rate stable).

## Reading guide / honest framing
- **The planner chains all three goals in one shot.** With the widened windows
  it now **acquires every goal reliably**: 3+1 hits A/B/C at 96/99/100%, 3+3 at
  100/100/100%. The terminal goal C is also **held** (98–100%). The "arbitrary
  terminal targets, chained" claim lands cleanly on both configs.
- **Intermediate goals are acquired but not held** (held % low for A, B) — a
  property of single-shot multi-goal planning, not a failure: the optimizer
  plans one smooth trajectory through all goals, so it begins slewing to the
  next goal before the current hold window ends (error dips to ~0 at each goal,
  then lifts as the next slew starts — visible in the figure). Only the final
  goal, with no successor to anticipate, is held. Headline the **acquisition**
  rates, not the window-end "held" rates.
- **Config gradient is still visible in the means.** 3+3 reaches each goal
  tighter (mean A 11.4° vs 3+1 22.8°) and holds the interior goals a bit better
  (held A/B 22/25% vs 10/14%) — the extra wheels buy margin — while both nail
  the terminal goal. Widening to 500 s lifted 3+1 goal-A acquisition from 45%
  (original 300 s) to 96% without erasing this gradient.
- The wheel-momentum inset shows the wheels charging/discharging across the goal
  sequence without saturation runaway.
