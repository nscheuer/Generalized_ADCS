class ADCS.controller.BDot(est_sat, gain)[source]¶

Bases: Controller

Implements the B-Dot detumbling controller.

The B-Dot algorithm is a magnetic control law used primarily for detumbling a satellite (reducing angular velocity) after deployment. It relies on the interaction between magnetic actuators (magnetorquers) and the Earth’s magnetic field.

Control Law

The controller calculates a desired magnetic dipole moment \(\mathbf{m}\) based on the rate of change of the measured magnetic field body vector \(\mathbf{B}\).

\[\mathbf{m}_{req} = -K \dot{\mathbf{B}}\]
Where:

  • \(\mathbf{m}_{req}\) is the requested magnetic dipole moment (\(Am^2\)).

  • \(K\) is the control gain (positive scalar).

  • \(\dot{\mathbf{B}}\) is the time derivative of the magnetic field vector in the body frame.

Physical Principle

The torque generated is \(\boldsymbol{\tau} = \mathbf{m} \times \mathbf{B}\). Substituting the control law:

\[\boldsymbol{\tau} = -K (\dot{\mathbf{B}} \times \mathbf{B})\]

For a tumbling satellite, the change in the magnetic field vector is dominated by the satellite’s rotation \(\boldsymbol{\omega}\) rather than the orbital change of the magnetic field. Therefore, \(\dot{\mathbf{B}} \approx \boldsymbol{\omega} \times \mathbf{B}\). This results in a torque that opposes the angular velocity perpendicular to the magnetic field, dissipating kinetic energy.

Hardware Prerequisites

This controller requires specific hardware interfaces defined in the EstimatedSatellite:

  1. Sensors: At least one MTM (Magnetometer) to measure \(\mathbf{B}\).

  2. Actuators: At least one MTQ (Magnetorquer) to generate \(\mathbf{m}\).

Matrix Mapping

This class automatically builds mapping matrices using the Moore-Penrose pseudoinverse to handle configurations with redundant sensors or coupled actuator axes.

Parameters:

  • est_sat (EstimatedSatellite) – The estimated satellite object containing hardware definitions.

  • gain (float) – The proportional gain \(K\) applied to the B-field derivative.

find_u(x_hat, sens, est_sat, os_hat)[source]¶

Computes the control signal based on the B-Dot law.

This method performs the following steps:

  1. Reconstruct B-field: Transforms raw sensor data sens into the magnetic field vector \(\mathbf{B}_{curr}\) using the pre-computed \(M_{read}\).

  2. Calculate Derivative: Computes the discrete time derivative \(\dot{\mathbf{B}}\) using a backward difference approximation:

    \[\dot{\mathbf{B}} \approx \frac{\mathbf{B}_{curr} - \mathbf{B}_{prev}}{\Delta t}\]

  3. Compute Dipole: Applies the gain \(\mathbf{m}_{desired} = -K \dot{\mathbf{B}}\).

  4. Map to Actuators: Converts the desired dipole to specific actuator commands via \(M_{act}\).

  5. Saturate: Limits the output to \(u_{max}\) of the specific magnetorquers.

Parameters:

  • x_hat (np.ndarray) – The current state estimate vector (unused in B-Dot, relies on raw sensors).

  • sens (np.ndarray) – The raw sensor measurements array.

  • est_sat (EstimatedSatellite) – The estimated satellite object (unused in loop, required by interface).

  • os_hat (Orbital_State) – The current orbital state estimate (used for J2000 timestamps).

Returns:

The computed control signal \(\mathbf{u}\) (e.g., duty cycles or voltages).

Return type:

np.ndarray

class ADCS.controller.Controller(est_sat, **kwargs)[source]¶

Bases: object

Base abstract controller for all ADCS control law implementations.

This class defines the core interface required in every ADCS controller. Controllers are expected to compute actuator input commands that achieve a desired torque or attitude regulation objective.

Parameters:

  • est_sat (EstimatedSatellite) – Estimated satellite model containing inertia, actuator layout, and sensor configuration.

  • **kwargs (dict) – Optional keyword parameters forwarded to derived controllers.

Notes

Controllers that inherit from this base must override find_u().

build_sensor_matrix_pinv(sensors, sensor_type)[source]¶

Constructs a measurement reconstruction matrix for a specific class of sensors by computing a Moore–Penrose pseudoinverse based on their sensing axes.

Given a stacked sensor measurement vector \(y\), this matrix maps sensor outputs to a physical 3-vector (e.g. the estimated magnetic field in body coordinates).

\[\mathbf{v}_{body} \approx M_{\mathrm{sens}} \, y\]
Parameters:

  • sensors (list[Sensor]) – List of all satellite sensors.

  • sensor_type (type) – Sensor type to extract. Must inherit from Sensor.

Returns:

  • M_sens (numpy.ndarray) – Pseudoinverse reconstruction matrix of shape (3, N), mapping measurements to a 3-vector physical estimate.

  • indices (list[int]) – Flattened measurement indices belonging to the selected sensor type.

Raises:

  • TypeError – If sensor_type does not subclass Sensor.

  • ValueError – If no sensors of the given type are found.

Return type:

Tuple[ndarray, List[int]]

build_torque_to_u_matrix_pinv(actuators, actuator_type)[source]¶

Builds the actuator allocation matrix that maps desired body torques into actuator command space via the pseudoinverse of the actuator direction matrix.

The columns of the internal matrix correspond to the unit axis directions along which the selected actuators can impart torque. Its Moore–Penrose pseudoinverse yields the minimum-norm command vector that best matches a desired torque.

\[\mathbf{u} \approx A^{\dagger} \, \boldsymbol{\tau}\]
Parameters:

  • actuators (list[Actuator]) – List of all satellite actuators.

  • actuator_type (type) – Target actuator type (e.g. RW or MTQ).

Returns:

  • M_act (numpy.ndarray) – Allocation pseudoinverse of size (N, 3), mapping desired torque to commands.

  • indices (list[int]) – Indices of the actuator channels belonging to the selected type.

Raises:

  • TypeError – If actuator_type does not subclass Actuator.

  • ValueError – If no actuators of the given type exist.

Return type:

Tuple[ndarray, List[int]]

build_u_to_torque_matrix_pinv(actuators, actuator_type)[source]¶

Builds the forward mapping matrix that converts actuator inputs directly into the physical torque contribution direction in the body frame.

Unlike build_torque_to_u_matrix_pinv(), which gives the inverse allocation mapping from torque to commands, this matrix is used in the forward physical model:

\[\boldsymbol{\tau} = A \, \mathbf{u}\]

Examples

  • For reaction wheels: each column of \(A\) is the torque axis direction.

  • For magnetorquers: each column represents the direction of the magnetic dipole. Body torque is then computed by

\[\boldsymbol{\tau} = \left[\mathbf{B}\right]_{\times} A \mathbf{u}\]
Parameters:

  • actuators (list[Actuator]) – List of all satellite actuators.

  • actuator_type (type) – Target actuator type.

Returns:

Matrix of stacked axis vectors, shape (3, N). If no actuators of the requested type are found, returns an empty (3, 0) matrix.

Return type:

numpy.ndarray

class ADCS.controller.MTQ_w_RW(est_sat, p_gain, d_gain, c_gain, h_target)[source]¶

Bases: Controller

Hybrid magnetic torque and reaction wheel controller.

This controller implements a three-axis ADCS control law which blends reaction wheel torque allocation with continuous momentum dumping via magnetic torquers. The implementation follows the core concepts of redundant wheel momentum management described by Hogan & Schaub [1]_, where wheel momentum states are actively controlled to remain bounded using MTQ torque authority.

The controller performs:

  • quaternion-based attitude regulation or target alignment,

  • PD angular rate feedback,

  • reaction wheel momentum reconstruction from state,

  • gyroscopic coupling compensation,

  • active momentum unloading,

  • magnetic dipole allocation via pseudo-inverse torque mapping,

  • actuator saturation handling.

The torque law can be summarized as:

\[\tau_{\text{att}} = -K_p \mathbf{q}_{\text{err}} -K_d (\boldsymbol{\omega} - \boldsymbol{\omega}_{\text{ref}}) + \tau_{\text{gyro}}\]

where

\[\tau_{\text{gyro}} = \boldsymbol{\omega} \times (J\boldsymbol{\omega} + \mathbf{h}_{rw})\]

and the commanded magnetic dipole vector \(\mathbf{u}_{mtq}\) is computed from a pseudo-inverse allocation of the momentum dumping torque

\[\tau_{dump} = -K_c(\mathbf{h}_{rw} - \mathbf{h}_{tgt})\]

subject to MTQ torque constraints

\[\tau_{mag} = \mathbf{u}_{mtq} \times \mathbf{B}\]

yielding the linearized form

\[\tau_{mag} = -[B]_\times \, \mathbf{A}_{mtq} \, \mathbf{u}_{mtq} = M_{mag} \, \mathbf{u}_{mtq}.\]

Reaction wheels apply the remaining torque after MTQ authority:

\[\tau_{rw} = \tau_{att} - \tau_{mag}.\]
Parameters:

  • est_sat (EstimatedSatellite) – Estimated satellite object containing inertia, actuator geometry, and sensor configuration.

  • p_gain (float) – Proportional gain \(K_p\) used for quaternion error feedback.

  • d_gain (float) – Derivative gain \(K_d\) used for angular rate feedback.

  • c_gain (float) – Momentum dumping gain \(K_c\) applied to wheel momentum deviation.

  • h_target (np.ndarray (shape: (3,))) – Desired body-frame reaction wheel momentum target in units of angular momentum. Dimensionality must match the number of RW axes.

Raises:

ValueError – If any dimension of h_target exceeds the maximum permitted reaction wheel storage, as determined by h_max.

Notes

This implementation assumes:

  • Wheel momentum states begin at index 7 of x_hat (i.e. x_hat[7:] maps directly to ordered RW indices)

  • Wheel axes align with internally-tracked actuator axis vectors

  • MTQs are torque-limited and can only generate torque orthogonal to the local magnetic field

The pseudo-inverse allocation is robust for full tri-axial MTQ configurations or over-actuated cases.

References

[1]

E. A. Hogan and H. Schaub, Three-Axis Attitude Control Using Redundant Reaction Wheels with Continuous Momentum Dumping, Journal of Guidance, Control, and Dynamics, Vol. 44, No. 3, 2021.

find_u(x_hat, sens, est_sat, os_hat, goal=None)[source]¶

Compute actuator commands for reaction wheels and magnetic torquers.

This method evaluates the sensor state, angular rate, quaternion orientation, and reaction wheel stored momenta to provide the hybrid torque solution. Magnetic torquers continuously unload reaction wheel momentum while reaction wheels primarily provide fine torque authority.

The spacecraft wheel momentum vector is reconstructed from the state:

\[\mathbf{h}_{rw} = \sum_i h_i \, \hat{a}_i\]

where h_i are the scalar momentum states x_hat[7:] and \(\hat{a}_i\) are normalized RW axis vectors.

Components of the total torque model:

  1. Attitude stabilization .. math:

    \tau_{\text{att}} =
-K_p \mathbf{q}_{err} - K_d (\omega - \omega_{\text{ref}})
+ \tau_{\text{gyro}}

  2. Gyroscopic coupling from wheels and body .. math:

    \tau_{\text{gyro}} =
\omega \times (J\omega + h_{rw})

  3. Momentum dumping .. math:

    \tau_{\text{dump}} =
-K_c(\mathbf{h}_{rw} - \mathbf{h}_{tgt})

  4. Magnetic allocation .. math:

    \tau_{mag} = M_{mag} \, u_{mtq}

    where

    \[M_{mag} = -[B]_\times A_{mtq}\]

Reaction wheel torque request is then

\[\tau_{rw} = \tau_{\text{att}} - \tau_{\text{mag}}\]

and actuator command vectors follow:

\[\begin{split}u_{rw} = M_{rw} \, \tau_{rw}\\ u_{mtq} = M_{mag}^+ \, \tau_{dump}\end{split}\]

Saturation is enforced using element-wise limiting.

Parameters:

  • x_hat (np.ndarray (shape: (10,))) –

    Estimated spacecraft state vector containing:

    • angular rates,

    • quaternion attitude,

    • reaction wheel momentum states.

  • sens (np.ndarray) – Raw sensor readouts. Only MTM channels are used to reconstruct the body magnetic field using the precomputed pseudo-inverse mapping.

  • est_sat (EstimatedSatellite) – Satellite model containing inertia and actuator geometry.

  • os_hat (Orbital_State) – Orbital state estimate providing the magnetic field \(B\) and atmospheric density for drag estimation if applicable.

  • goal_vector_eci (np.ndarray, optional) – Optional inertial-frame target direction. If provided, the controller operates in a pointing mode, forming the quaternion error from the boresight cross product.

  • w_ref (np.ndarray, optional) – Desired angular rate vector. Defaults to zero if omitted.

  • goal (Goal | None)

Returns:

u_total – Full actuator command vector ordered by actuator index in est_sat.actuators. Reaction wheel torques occupy the RW allocation slots and MTQ current/command magnitudes occupy the MTQ slots.

Return type:

np.ndarray

See also

skewsym(), normalize(), build_torque_to_u_matrix_pinv(), RW, MTQ

Notes

  • MTQs produce no torque component parallel to \(\mathbf{B}\).

  • Reaction wheel torque authority is constrained by rw.max_torque and their energy storage h_max.

  • This controller assumes RW momenta are stored in x_hat[7:] in the same order as RW indices.

References

[1]

E. A. Hogan and H. Schaub, Three-Axis Attitude Control Using Redundant Reaction Wheels with Continuous Momentum Dumping, Journal of Guidance, Control, and Dynamics, Vol. 44, No. 3, 2021.
